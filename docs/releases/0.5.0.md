# Shared Tasks 0.5.0 (draft)

> **Draft, not published.** These notes are prepared before the release. The
> checksums, the build commit and the release date are placeholders and are
> filled in when the owner tags 0.5.0. Nothing here says a release exists.

Shared Tasks 0.5.0: collaboration you can do without knowing the commands. A
visible pane and a card on the section lead you through sharing, inviting and
joining, show what needs attention with a direct way to fix it, and pick up
unfinished work after a restart. For catalog users updating from 0.4.2.

**Requires Obsidian 1.13.4 or later**, as 0.4.x.

The Markdown format of your notes and the sync protocol are unchanged. The
command palette commands keep their names and still work.

## What is new since 0.4.2

- **The Shared Tasks pane.** One pane per workspace, opened from the ribbon
  icon ("Open Shared Tasks pane"), the command of the same name, the section
  card, or the editor's context menu. It follows the note you are in and
  offers the next step for the cursor: "Share section…" on a heading,
  "Invite collaborator…" on a shared section, "Insert into a note…" for a
  section you joined and have not placed yet. It lists the shared sections
  this device knows, where each is used, and what needs attention.
- **Share, then invite, in one place.** Before you confirm, the pane shows
  what a share will publish (the lines, the sync server, how comments are
  handled). It says whether the section is on its server yet and offers the
  invitation only when it is ready. An invitation says "One-time link, does
  not expire; whoever opens it first joins." and you choose Read or
  Read + write each time. "Link copied" means the link is on the clipboard:
  Shared Tasks does not send it.
- **Join with a pasted link, then choose where it goes.** "Join with a
  link…" shows each step (the server accepted the claim, your access, the
  section loaded), then inserts the section into a note you choose, with a
  readable preview. A join you give up on, or one whose answer was lost, can
  be checked again; it is never started a second time.
- **Problems with a direct way to each fix.** A problem hub lists what needs
  attention and opens the matching conflict dialog or "Repair shared sections
  in this note". Local text that has not been sent is told apart from what
  the server has accepted and from an empty queue.
- **Unfinished work resumes after a restart.** A share, an insert or a join
  cut short by closing Obsidian continues under its own operation instead of
  starting over.
- **Tips on demand.** Short tips explain an action when it is offered. "Hide
  tip" hides one in this vault; "Show tips again" brings them back. No tour
  opens on install or update.
- **Neutral wording.** Texts about sections no longer speak of
  "collaborations"; the older shared-task commands no longer offer a shared
  section as if it were a task collaboration.
- **Faster pane.** A cursor move redraws the pane at once.

## Fixed since 0.4.2

- **Pasted lines are not overwritten.** A Task or paragraph pasted into a
  section that already syncs, which this device's sync record did not know,
  is held for your choice instead of being replaced by the shared version.
  This closes the known limit of 0.4.2
  ([#41](https://github.com/openlfcp/obsidian/issues/41)). "Repair shared
  sections in this note" shows both versions.
- **A line Obsidian's merge dropped comes back.** The status says the line is
  missing and points to "Repair shared sections in this note", which offers
  to put it back.
- **A second Share is not stuck.** Sharing two sections quickly, or Share
  right after the plugin loads, no longer leaves a section "hosting pending"
  without a message, and no longer creates its server record twice. A
  section already damaged this way is repaired
  ([#72](https://github.com/openlfcp/obsidian/issues/72)).
- **A deletion made while a section is suspended is kept.** It is sent when
  the section resumes and no longer reads as a lost binding
  ([#57](https://github.com/openlfcp/obsidian/issues/57)).
- **A resumed edit is kept after a lost line.** A batch of edits saved before
  a restart is no longer sent twice when a line it touched was lost in
  between.
- **The first click on a pane button counts** ("Join with a link…" after a
  restart, "Remove access…").
- **An honest insert preview.** It no longer says "Not inserted in any note
  yet" for the note the section came from.
- **Notes you delete.** The local record of a deleted note is forgotten, a
  copy of its text you did not resolve is kept until you discard it, and a
  record of a note missing for 30 days is cleaned up. Your own text is never
  removed by that cleanup.
- **A clearer stopped-syncing notice.** It names the section and says "the
  sync server" instead of printing the server address (the address stays in
  "Resource status"). A single conflict shows one "Review conflicts" button.
- **No work after unload.** A pending status pass no longer runs after the
  plugin is unloaded.
- **Fewer races.** Saving a note's sync record and its journal no longer
  interleave when two passes overlap.
- **Under the hood.** The TypeScript SDK is `@openlfcp/*` 0.2.2; spec
  `mvp-0.2-baseline.12`; the project server runs the reference server 0.3.2,
  unchanged.

## Install and upgrade

From Settings → Community plugins → Updates. Your identity, keys, shared
sections, queued edits and unfinished operations are kept. The update opens
no tour and no dialog, because the sync data format is the same (IndexedDB
database version 2). The upgrade from 0.4.1 and 0.4.2 was rehearsed in real
Obsidian ([report](../devel/reports/upgrade-rollback-perf-0.5.md)).

Going from 0.3.x straight to 0.5.0 is as for 0.4: the sync data is upgraded
once and 0.3.x cannot open it afterwards ([details](0.4-compatibility.md)).

By hand: put `main.js`, `manifest.json` and `styles.css` from the release
page into `<vault>/.obsidian/plugins/shared-tasks/` and compare them with

## Rolling back to 0.4.2

Install 0.4.2 over 0.5.0 (BRAT: choose version 0.4.2 for `openlfcp/obsidian`,
or put 0.4.2's three files into the plugin folder). It starts on the data
0.5.0 wrote: the same identity and sections, queued edits sent, an
unfinished share finished. The pane is a 0.5 feature and is not in 0.4.2;
hidden tips come back. Roll back to 0.4.2, not 0.4.1, which lacks the 0.4.2
fix for Task edits in copied sections. Going to 0.3.x is not supported.

Not rehearsed: after a rollback, a kept copy of a deleted note's text may not
show in the card (the text is not deleted); and if a crash cuts the cleanup
of a cancelled share before you roll back, 0.4.2 can list the section that
was never hosted as an ordinary one, with no data lost
([#53](https://github.com/openlfcp/obsidian/issues/53)).

## Known limits

- **Desktop first.** Tested by hand on desktop only; automated runs use real
  Obsidian 1.13.4 and 1.14.4 on Linux, macOS and Windows runners. Not tested
  by hand: Windows or Linux desktops, an input method (IME), mobile. Shared
  sections are read-only on mobile and nothing about them was tried on a
  real device.
- **Wording of the pane** was not checked with people before this release;
  expect rough edges.
- **A late move can be sent twice**, and a task link can be missing after a
  Task is completed; the wording of a revoke notice is rough
  ([#68](https://github.com/openlfcp/obsidian/issues/68)).
- **Repeat signs do not sync.** The recurrence of a Task (🔁) stays on the
  device that has it, by design, so two notes can show different titles of a
  repeating Task. The date and the done state sync.
- **Put back after a lost marker and an edit.** If a line lost its marker and
  was edited in the same place, "Put back" can add a second copy. Check the
  line after Repair.
- **0.4.1 and 0.4.2** keep the double-creation race and lack the fix for a
  newcomer who joins just after the inviter restarted; no 0.4.3 is planned.
- **Project server quotas.** 24 open connections in all and 8 per network
  address, 200 collaborations per identity, 50 new ones a day from one
  address; past a limit an action is refused with "quota exceeded" and
  nothing already shared is lost.
- **No notion of "seen".** A ✓✓ means shared, not read. There are no read
  receipts, no state of an invitation, no inbox, and no way to cancel an
  unused invitation or give it an expiry. A link works once, for whoever
  opens it first.
- **Beta software; not for data you need to protect.** Data on the public
  server can be lost.
- From 0.4: about 200 tasks is the qualified size of a section, no headings
  inside a section, one server per collaboration. See the
  [0.4.0 notes](0.4.0.md) and the README's Limitations.
