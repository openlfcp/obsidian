Shared Tasks 0.4.0-beta.10: the tenth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.9

This beta fixes two ways Shared Tasks said less than the truth about a
shared section.

**Edits that are not sent now say so.** A heading typed inside a shared
section, a damaged marker or task line, or an edit in a section you can
only read stopped everything in that copy from being sent, yet the
section's details said "No local changes waiting." and "Current as last
checked", the note marked nothing and no notice came. Now:

- a notice says once how many edits are not sent and why, with the line;
- the details count them ("2 edits not sent: the section has content it
  cannot share (Plan.md, line 12)."), say what to do, never claim the
  section is current while an edit is held, and offer **"Go to line …"**
  and, where it helps, **"Repair shared sections in this note"**;
- the lines concerned show "Needs attention", and "Go to next shared
  section problem" reaches them.

**Typing into a section you can only read is stopped.** It used to be
taken and then never sent. Now it is not applied, and a notice says the
section is read-only for you. An edit that reaches the note another way
(another plugin, a file sync tool) stays in your note, is not sent, and
is counted in the details as above.

**"Share section…" twice no longer leaves a stray collaboration.** Run
twice on one note, it opened two previews; sharing from both shared the
section once but left a second collaboration behind, never on the
server, listed in "Resource status" and reported as "stopped syncing …
RESOURCE_NOT_HOSTED". Now one share (or insert) runs
per note at a time, and a second one is told to wait; "Join
collaboration" runs once at a time too. A share whose note changed before
it finished leaves nothing behind.

**Requires Obsidian 1.13.4 or later.**

## Good to know

**A stray collaboration from an earlier beta stays listed.** One left by
"Share section…" run twice before this beta is not removed. It was never
on the server and no note uses it; it is safe to ignore.

**Undo brings a held copy back.** Undo the edit, or move the heading
below the section's end marker, and the section syncs again by itself.

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.10.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.2.0-beta.6, as in 0.4.0-beta.9
  (exact versions, from npm with provenance, dist-tag `beta`).
- Spec `mvp-0.2-baseline.10`. Tested against the reference server at
  `814e913` (the baseline.10 pin).
- The SDK's storage has no deletion: the Resource of a share given up
  before it was hosted is closed, no longer listed or opened, and its
  stored rows stay on the device, marked as discarded.
- A new section's Resource counts as "hosting pending" from its creation,
  so a refusal that comes before it is hosted is expected, not announced.
- The status facts keep "not a member" apart from "access removed", and
  carry when access was last verified and whether that view is current.
- Checked in real Obsidian 1.13.4 and 1.14.4: "Share section…" twice, and
  the details, marks and notices of edits held by a heading inside the
  section, a damaged marker and a read-only copy.
- The randomized typing test of 0.4.0-beta.9 runs again in its extended
  form: 500 sequences pass.
