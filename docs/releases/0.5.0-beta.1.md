# Shared Tasks 0.5.0-beta.1 (candidate)

> **Candidate, not published.** These are the notes for the 0.5.0-beta.1
> candidate (LFCP-03-027). The files, their checksums and the commit they were
> built from are fixed below. No tag and no release page exist yet: the
> owner creates them. Nothing here says a release exists.

Shared Tasks 0.5.0-beta.1: a pane that leads you through sharing a section,
inviting someone and joining, without needing the command palette. A
pre-release for a pilot with new users; install it with BRAT. Catalog users are
not updated.

**Requires Obsidian 1.13.4 or later**, as 0.4.x.

## New since 0.4.2

- **The Shared Tasks pane.** One pane per workspace, opened from the ribbon
  icon ("Open Shared Tasks pane"), the command of the same name, the section
  card, or the editor's context menu. It follows the note you are in and
  offers the next step for the cursor: "Share section…" on a heading,
  "Invite collaborator…" on a shared section, "Insert into a note…" for a
  section you joined and have not placed yet. It lists the shared sections
  this device knows, where each is used, and what needs attention. The
  command palette commands keep their names and still work.
- **Share, then invite, in one place.** The pane shows what a share will
  publish (the lines, the sync server, how comments are handled) before you
  confirm, says whether the section is on its server yet, and offers the
  invitation only when it is ready. An invitation says "One-time link, does
  not expire; whoever opens it first joins." and you choose Read or
  Read + write each time. "Link copied" means the link is on the clipboard:
  Shared Tasks does not send it.
- **Join with a pasted link, then insert.** "Join with a link…" takes a link
  you paste, shows each step (the server accepted the claim, your access, the
  section loaded), then inserts the section into a note you choose, with a
  readable preview. A join you give up on, or one whose answer was lost, can
  be checked again; it is never started a second time.
- **Problems with a direct way to each fix.** A problem hub lists what needs
  attention and opens the matching conflict dialog or "Repair shared sections
  in this note". Local text that has not been sent is told apart from what
  the server has accepted and from an empty queue.
- **Unfinished work resumes after a restart.** A share, an insert or a join
  cut short by closing Obsidian continues under its own operation instead of
  starting over.
- **A line Obsidian's merge dropped comes back.** When Obsidian merges two
  views of a note and a shared line goes missing, the status says the line
  is missing and points to "Repair shared sections in this note", which
  offers to put it back. Nothing in the pane or the status calls it lost any
  more.
- **A second Share is not stuck.** Sharing two sections quickly, or Share right
  after the plugin loads, no longer leaves one "hosting pending" without a
  message, and no longer creates the section's server record twice.
- **The first click on a pane button counts.** "Join with a link…" after a
  restart and "Remove access…" act on the first click.
- **An honest insert preview.** The preview no longer says "Not inserted in
  any note yet" for the note the section came from.
- **Notes you delete.** The local record of a deleted note is forgotten, a
  copy of its text you did not resolve is kept until you discard it, and a
  record of a note missing from the vault for 30 days is cleaned up after the
  notes are read and then daily. Your own text is never removed by that
  cleanup.
- **Pasted lines are not overwritten.** A Task or paragraph pasted into a
  section that already syncs, which this device's sync record did not know,
  is held for your choice instead of being replaced by the shared version.
  This closes the known limit of 0.4.2
  ([#41](https://github.com/openlfcp/obsidian/issues/41)). "Repair shared
  sections in this note" shows both versions.
- **A resumed edit is kept after a lost line.** A batch of edits saved before
  a restart, whose note was not written yet, is no longer sent twice when a
  line it touched was lost in between.
- **Shared sections stay out of the 0.1 task pickers.** The older shared-task
  commands no longer offer a shared section as if it were a task
  collaboration.
- **Tips on demand.** Short tips explain an action when it is offered. "Hide
  tip" hides one in this vault; "Show tips again" brings them back. No tour
  opens on install or update.
- **Neutral wording on section surfaces.** Texts about sections no longer
  speak of "collaborations".
- **Faster pane.** A cursor move redraws the pane at once; only the moves
  right after it are grouped.
- **Fewer races.** Saving a note's sync record and its journal no longer
  interleave when two passes overlap.
- **Under the hood:** the TypeScript SDK is `@openlfcp/*` 0.2.2 (one commit
  for an invitation's grant and Key Package; a failing listener no longer
  interrupts a change). Spec `mvp-0.2-baseline.12`; the project server runs
  the reference server 0.3.2, unchanged.

Unchanged: the notes' Markdown format, the sync protocol and the sync data
format on this device (IndexedDB database version 2).

## Install

Needs Obsidian 1.13.4 or later. Desktop first: this beta is tested by hand
only on desktop (see Known limits).

**With BRAT (the way to try this beta):**

1. Install and enable [BRAT](https://github.com/TfTHacker/obsidian42-brat)
   from Settings → Community plugins.
2. Run "BRAT: Add a beta plugin for testing", enter `openlfcp/obsidian`, and
   choose **Latest version** (a specific version is pinned and BRAT will not
   update it).
3. Enable "Shared Tasks" in Settings → Community plugins and check that the
   version listed is `0.5.0-beta.1`.

**By hand:** from the release page, download `main.js`, `manifest.json` and
`styles.css` into a new folder `<vault>/.obsidian/plugins/shared-tasks/`, then
enable the plugin. Compare the files with the checksums below before you
enable it.

## Upgrading from 0.4.x

Install the beta over 0.4.1 or 0.4.2 (BRAT does this when you add it). Your
identity, keys, shared sections, queued edits and unfinished operations are
kept; an unfinished share or insert is finished under its own operation. The
update opens no tour and no dialog, and prints no "upgraded" notice, because
the sync data format is the same. The upgrade was rehearsed in real Obsidian
from 0.4.1 and 0.4.2 on macOS and Ubuntu with a queued edit and an unfinished
share ([report](../devel/reports/upgrade-rollback-perf-0.5.md)).

Going from 0.3.x straight to this build is as for 0.4: 0.4 upgrades the sync
data once, and 0.3.x cannot open it afterwards
([details](0.4-compatibility.md)).

## Rolling back to 0.4.2

To go back, install 0.4.2 over the beta (BRAT: choose version 0.4.2 for
`openlfcp/obsidian`, or put 0.4.2's three files into the plugin folder). It
starts on the data the beta wrote: the same identity and sections, queued
edits sent, an unfinished share finished, no "newer version" notice. This was
rehearsed (beta build, then 0.4.2, then the beta again). What you lose:
the hidden tips come back if 0.4.2 saves its settings; the pane is a 0.5
feature and is not there in 0.4.2. Roll back to 0.4.2, not 0.4.1, which lacks
the 0.4.2 fix for Task edits in copied sections. Not supported: going to
0.3.x.

## Known limits

- **Pane timing.** The pane's redraw after a cursor move was measured at
  p95 127 to 161 ms on a CI runner against a 150 ms goal before the redraw
  was made immediate (three of six series over). After that fix
  ([#54](https://github.com/openlfcp/obsidian/pull/54)) two runs on a
  macOS CI runner (runs 39063168092 and 39063609331, 200-task section, on a
  temporary branch with the same pane code) gave p95 119.0 to 136.5 ms, all
  six series within 150 ms, with a small margin. The measurement on the
  exact beta files is `TBD (phase 2)`; another machine can come out
  slower.
- **Pilot first.** No real people have used the pane yet. Whether new users
  find sharing without knowing a command is what the pilot of this beta
  checks, so expect rough edges in the wording.
- **Not tested by hand:** a physical desktop other than CI runners, Windows
  or Linux by hand, an input method (IME), or mobile. Shared sections are
  read-only on mobile and nothing about them was tried on a real device.
- **A deletion made while a section is suspended.** A line you delete while
  a section is waiting (for example after a lost binding) can show up as a
  lost binding on later passes until you run "Repair shared sections in this
  note". No data is lost
  ([#57](https://github.com/openlfcp/obsidian/issues/57)).
- **Put back after a lost marker and an edit.** If a line lost its marker and
  its text was changed in the same place, "Put back" can add a second copy of
  the line. Check the line after Repair.
- **A section whose server record was damaged by the double creation of
  0.4.x.** Share right after the plugin loads could create the server record
  twice in 0.4.1 and 0.4.2 (fixed in this beta: it cannot happen again).
  A section already damaged shows "the DEK is not the one committed for epoch
  0" on every save and "Check the result" answers "not known". This beta does
  not repair it yet
  ([#72](https://github.com/openlfcp/obsidian/issues/72)). Workaround: stop
  sharing that section, discard it, and share it again; the text of your note
  stays. The probability is low and no 0.4.3 patch is planned.
- **Smaller known issues of the pane.** A second `node.move` can be sent for one
  move, a task link can be missing after a Task is completed, and the text of
  a revoke notice is rough
  ([#68](https://github.com/openlfcp/obsidian/issues/68)).
- **0.4.x.** 0.4.1 and 0.4.2 have the double-creation race above and lack
  the fix for a newcomer who joins just after the inviter restarted: the
  invitation waits for the epoch's snapshot only in this beta
  ([#73](https://github.com/openlfcp/obsidian/pull/73)). The newcomer then
  cannot load the section until the inviter retries; no access is leaked. A 0.4.3
  patch is not planned; report it if you meet it.
- **Project server quotas.** The server accepts 24 open connections in all
  and 8 per network address, 200 collaborations per identity, 50 new ones a
  day from one address. Several people on one network share the per-address
  limit; past a limit the action is refused with "quota exceeded" and nothing
  already shared is lost.
- **No notion of "seen".** A ✓✓ on a section means it is shared; it does not
  mean anyone has read it. There are no read receipts, no delivery state of
  an invitation, no inbox of incoming invitations, and no way to cancel an
  unused invitation or give it an expiry. An invitation link works once, for
  whoever opens it first.
- Everything else from 0.4: section size (about 200 tasks is the qualified
  size), no headings inside a section, local-only Tasks tokens, one server
  per collaboration, data on the public server can be lost. See the
  [0.4.0 notes](0.4.0.md) and the README's Limitations.
