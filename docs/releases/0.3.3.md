Shared Tasks 0.3.3 (beta): a security fix. Update soon.

**Requires Obsidian 1.13.4 or later**, as 0.3.2.

## Fixes

- **A collaborator could make a collaboration fail to open on your device.**
  Someone with write access to a collaboration could send a change that
  Shared Tasks accepted but could not save and load again: after the next
  start of Obsidian, that collaboration no longer opened on the devices that
  had received it. Your notes were never changed, and other collaborations
  were not affected. 0.3.3 refuses such changes before they reach the
  shared state (OpenLFCP SPEC-PATCH-10).
- **Such collaborations recover without reinstalling.** If a collaboration
  on this device no longer opens for this reason, 0.3.3 rebuilds its state
  from the changes stored on this device, leaves out the invalid ones, and
  says so once ("… is being rebuilt from the changes stored on this
  device"). Nothing needs to be removed or joined again. Edits you made
  that the server had not received yet come back once it has them.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.1.4 (exact versions, from npm with
  provenance): it checks the canonical change encoding and the operation
  references of every received change before its Automerge engine sees it.
- Spec `mvp-0.1-baseline.10`, server 0.3.0.

## Install and upgrade

From Community plugins (Settings → Community plugins → Updates), with BRAT
(`openlfcp/obsidian`), or by hand: put `main.js`, `manifest.json` and
`styles.css` from the release page into
`<vault>/.obsidian/plugins/shared-tasks/`. Your identity, collaborations and
settings are kept.
