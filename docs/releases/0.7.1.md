# Shared Tasks 0.7.1

Shared Tasks 0.7.1 fixes linked devices from 0.7.0, found by the final review
of the specification. For catalog users updating from 0.7.0.

**Requires Obsidian 1.13.4 or later**, as 0.7.0.

The Markdown format of your notes is unchanged.

## What changed since 0.7.0

- **Pairing no longer adds a record to every shared section.** In 0.7.0,
  every device you added (and every link you cancelled) left a record in each
  section you share. A section allows a limited number of such records, and
  once it was full, removing a lost device could no longer be recorded there.
  Pairing now adds nothing to your sections; removing a device still revokes
  it in every section where it could act, and a section where it could not
  act gets no record and is not mentioned.
- **Removing a device keeps a name conflict.** When two of your devices
  renamed the same device at the same time, removing it no longer picks one
  of the names silently; both stay until you choose.
- **A server without device support is named.** "Add my other device…" on a
  sync server that no longer supports devices says so, makes no link and
  sends nothing there.

Sections that already hold records from pairings in 0.7.0 keep them; they do
no harm, and the limit is now reached only in rare cases (see Known limits).

## Install and upgrade

From Settings → Community plugins → Updates. Nothing to migrate.

By hand: put `main.js`, `manifest.json` and `styles.css` from the release
page into `<vault>/.obsidian/plugins/shared-tasks/` and compare them with
these checksums.

Built by CI from the commit the tag `0.7.1` points to; the release page
carries a build provenance attestation: `gh attestation verify main.js
--repo openlfcp/obsidian`.

## Rolling back to 0.7.0

Install 0.7.0 over 0.7.1 (BRAT: choose version 0.7.0 for
`openlfcp/obsidian`, or put 0.7.0's three files into the plugin folder). The
data format is the same; pairing then adds records to your sections again.

## Known limits

As in [0.7.0](0.7.0.md#known-limits), plus:

- A device removed before it was ever added to a section, while that section
  already holds 64 such early revocations of your devices, can still join it
  by itself until your next "Finish now" or the next automatic check removes
  it there.
