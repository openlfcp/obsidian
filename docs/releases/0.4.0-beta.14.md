Shared Tasks 0.4.0-beta.14: the fourteenth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.13

**A collaborator's edits no longer get reverted while your note is open
and you aren't typing.** Every second edit in a row used to be silently
undone: after Shared Tasks wrote a collaborator's change into your open
note, it read the next change against the text from before that write,
took the difference for an edit of yours, and sent the old text back to
everyone. Nothing told you or them. Please update, and ask your
collaborators to update too: a member still on an earlier beta can keep
undoing the others' edits while their note is open.

**A task nested under one a collaborator cut is no longer hidden.** If you
cut a task while a collaborator nested another task under it, the nested
task disappeared from both notes, with nothing to review. It now stays
where your note shows it. This was the known issue of 0.4.0-beta.13.

**A task a collaborator moves under a new task right after its old one
arrives whole.** It could leave the new task as " [ ] task", no longer a
task, with the moved one still at its old place, and the section stopped
syncing for you.

**A task you move right after one you just pasted stays after it.** Paste
a cut task somewhere and move another task to just after it: the moved
task went back to where the cut was taken from, for everyone.

**Requires Obsidian 1.13.4 or later.**

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.14.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- A pass on an open note reads the editor's document as it is, not the
  copy the coordinator keeps for scheduling. After a written pass the
  coordinator learns the text written, as the note's source and as
  reconciled, for both routes (a closed note's next pass no longer reads
  the file from before the rewrite). The engine checks the source is still
  current before planning and before each section commits: a stale one
  commits and writes nothing, and the host passes again on the current text.
  New native spec section-idle-remote: a collaborator's edits in a row while
  the note is idle.
- A pass that deletes a node places the model's children of it that the
  note shows elsewhere where the note shows them (a nesting received
  before the cut's pass is not concurrent with it: nothing to review).
- The structural writer moves what an update placed inside lines a move
  takes away to where those lines began, in order, before the moved node.
- A batch's placements go in an order the model takes one by one: each
  after the placement of the node it follows or goes under.
- The peer-structure property test takes the editor's hints as the editor
  gives them, counts what reappeared as Review conflicts lists it, and
  pastes a cut at the level it goes to. It passes 999 of seeds 1–1000; the
  one left (a paste while the section waits for Review conflicts, then
  Keep) is being fixed.
- Unchanged: `@openlfcp/*` 0.2.0-beta.7, spec `mvp-0.2-baseline.12`, the
  reference server at `138030a`, 49 fixtures.
