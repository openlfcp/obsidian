Shared Tasks 0.4.0-beta.7: the seventh beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.6

**Typed text is never sent twice.** A word typed (or composed with an
input method) at the end of a paragraph, followed at once by a new line in
another place, such as Enter on a task line, could be sent twice: the
other vaults showed the word twice, this vault's note lost it, and the
section stayed at "Changes are not safely saved for sync", with every
later edit of that paragraph refused. Typing that waits to be sent and
the next change of the section can no longer cross: each is sent once.

**A vault left in that state heals by itself.** At its next pass, the
section shows the shared text again, as the other vaults have it, and
Shared Tasks says so once. Nothing is deleted from the shared section: if
the word shows twice, delete one by hand, as an ordinary edit. The text
this vault could not send stays on this device as a local copy; the
section's card offers to discard such copies ("Discard N local
copies…").

**Review conflicts keeps your choices and names each place.**

- A choice made on one question is kept when you apply another; nothing
  is chosen for you, and Apply waits for your choice.
- A task moved to two places offers each place by its position ("First
  in the section", 'After Task "First task"'), not "The section's top
  level" twice, and the place you choose is where the task goes (before,
  either choice put it first).
- A task that two vaults moved by cut and paste no longer also asks
  whether it "was restored in two places": two equal changes agree, and
  the section no longer needs attention for them.

**Offline sooner.** When the network goes away without the system
saying so (on macOS while another network interface stays up), a section
showed as synced for up to 90 s. Shared Tasks now checks a silent
connection after 15 s and shows offline about 20 s after the network is
gone, then reconnects as soon as it can.

**Requires Obsidian 1.13.4 or later.**

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.7.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.2.0-beta.6, as in 0.4.0-beta.6
  (exact versions, from npm with provenance, dist-tag `beta`).
- Spec `mvp-0.2-baseline.10`. Tested against the reference server at
  `814e913` (the baseline.10 pin).
- The connection check sends a `PING` after 15 s without any message and
  closes the connection when nothing answers within 5 s (LFCP-WIRE-01
  §38: every message counts). Measured on Linux with the network turned
  off: offline after 20 s, against 90 s without it.
- Checked in real Obsidian 1.13.4 and 1.14.4, including the input method
  sequence of the owner's check (simulated composition, a real Enter in
  Live Preview) and a vault left in the doubled state.
- For what changed in 0.4.0-beta.6 (input methods, a second section on
  one server, invitations, refused is not offline), see
  [0.4.0-beta.6.md](0.4.0-beta.6.md).
