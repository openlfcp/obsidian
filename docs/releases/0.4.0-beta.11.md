Shared Tasks 0.4.0-beta.11: the eleventh beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.10

This beta fixes the ways of moving a task that could still give your move
to its neighbour, or hold it back without a word.

**Move line up / down moves the task you are on.** Obsidian's "Move line
up" on a task moved its neighbour down instead, as the editor sees it, so
your move was sent as the neighbour's: when a collaborator moved the same
task elsewhere offline, no conflict came and their move silently won. Now
Move line moves the whole task you are on, with its ref line and its
subtasks, past the task before or after it, and that task is the one
sent. At the first or last task of a list it does nothing, so a task
never leaves its ref line or the section behind.

**Tab and Shift+Tab take the ref line along.** Indenting a task under the
one above left its ref line where it was, so the ref bound the wrong
task. Its ref line and subtasks are now indented or outdented with it.

**A task pasted without its line break is put on its own lines.** A task
selected to the end of its ref line, without the line break, then pasted
at the start of another task's line, glued that line to the ref; the copy
was then held and your move was not sent. Pasting at the end of a line
had the same effect. The paste now gets the line break it lacked, and the
move is sent.

**A selection never ends halfway through a ref line.** In a narrow
window, Shift+Down over a task and its long, wrapped ref line could stop
in the middle of the ref, and a cut took half of it. A selection that
ends inside a ref line or marker now ends at its end (or its start, going
back).

**A held copy names the tasks moved in it.** When a copy is held (a
heading inside the section, a damaged marker), a task you moved in it is
now counted with the edits not sent, and the details name it: "Moved,
not sent: “Gamma”."

**Requires Obsidian 1.13.4 or later.**

## Good to know

**A drag of selected text** within the editor is a cut and a paste in
one: the text you dropped is the task that moved. Obsidian 1.14 has no
drag handle on list items.

**A task cut with its next one.** In Live Preview, where ref lines are
hidden, Shift+Down from the start of a task's line selects that task and
the whole next one; cut and paste moves both, as you see them.

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.11.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.2.0-beta.6, as in 0.4.0-beta.10
  (exact versions, from npm with provenance, dist-tag `beta`).
- Spec `mvp-0.2-baseline.10`. Tested against the reference server at
  `814e913` (the baseline.10 pin).
- In a shared section, the editor's own line moves are turned into moves
  of whole nodes in the same transaction (one undo step): Move line
  (`move.line`), Tab and Shift+Tab (`input.indent`, `delete.dedent`), a
  paste that runs into the line around it (`input.paste`, `input.drop`),
  and a selection that ends inside a binding line (`select`).
- A Move line tells the pass which nodes moved (the ones under the
  selection) and that nothing was removed; its change rewrites both
  nodes' lines, and CodeMirror expresses moving a task up as moving its
  neighbour down.
- Edits held in a copy now include a task moved among its siblings, not
  only one moved to another parent.
- Checked in real Obsidian 1.13.4 and 1.14.4, both vaults offline while
  the other moves the same task to the section's start: Move line up; the
  keys of the beta.10 check (Shift+Down twice from the start of a task's
  line, cut, Up to the previous task's line, paste) in Source mode and in
  Live Preview; a task cut without its line break and pasted at the
  start of another task's line. Each ends in a conflict on that task on
  both sides. Tab: the ref line follows, and the task is a subtask on
  both sides.
- The randomized test now also moves tasks by Move line, by a drag, by a
  paste glued to the next line, and by Tab then Shift+Tab, and checks that
  no pass holds anything back. 500 sequences pass.
- A read-only console trace of the editor's transactions and the
  plugin's passes (CodeMirror's own event names, the changes, what each
  pass took and the moves it journaled) was used to compare macOS and
  Linux; it is not part of the plugin.
