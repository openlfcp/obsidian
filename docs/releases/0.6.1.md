# Shared Tasks 0.6.1

Shared Tasks 0.6.1 gets your plugin ready for linked devices (one person,
several devices), which a later version adds. Nothing changes for you until
someone you share a section with starts using them. For catalog users
updating from 0.6.0.

**Requires Obsidian 1.13.4 or later**, as 0.6.0.

The Markdown format of your notes and the sync protocol are unchanged.

## What changed since 0.6.0

- **A section that uses linked devices says so.** When someone you share a
  section with adds or removes one of their devices in a later version of
  the plugin, this version cannot follow that section any more. Instead of a
  generic error or endless loading, the section stops syncing with **"This
  section now uses a person's linked devices… Update the plugin"**, and says
  it again after a restart. Its copy in your note stays readable; edits you
  make here wait on this device and are sent after you update.
- **Join tells a device link from an invitation.** A link to add a device
  (`lfcp://pair/…`) pasted into **"Join with a link…"** is answered with
  **"This is a link to add a device, not an invitation…"**, and nothing is
  used up.

## Install and upgrade

From Settings → Community plugins → Updates. Nothing to migrate: identity,
keys, shared sections, queued edits, settings and hotkeys are kept.

By hand: put `main.js`, `manifest.json` and `styles.css` from the release
page into `<vault>/.obsidian/plugins/shared-tasks/` and compare them with
these checksums.

## Rolling back to 0.6.0

Install 0.6.0 over 0.6.1 (BRAT: choose version 0.6.0 for
`openlfcp/obsidian`, or put 0.6.0's three files into the plugin folder).
The data format is the same. A section that uses linked devices then fails
with a generic error again instead of the message above.

## Known limits

As in [0.6.0](0.6.0.md#known-limits), plus:

- Linked devices themselves are not in this version: it only recognises a
  section that uses them and stops there, keeping your copy and your edits.
