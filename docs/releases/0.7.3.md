# Shared Tasks 0.7.3

Shared Tasks 0.7.3 makes changing a section's key safer and more reliable
after you remove a device. For catalog users updating from 0.7.2.

**Requires Obsidian 1.13.4 or later**, as 0.7.2.

The Markdown format of your notes and the sync protocol are unchanged. It
uses the OpenLFCP SDK 0.5.1.

## What changed since 0.7.2

- **A removed device gets no new keys.** After you remove a device, Shared
  Tasks changes the key of your shared sections. Before 0.7.3, a retry of
  that change could hand the new key to the removed device, or to a device
  added through it. This happened when a section's server had not yet
  recorded the removal. Every key change and every retry now leaves out the
  devices removed in your device list. While your device list has two
  conflicting versions on the server, no key is handed on for you until
  that is resolved. Without a device list, key changes work as before.
- **Handing on a new key survives interruptions.** If Obsidian closes, or
  the connection drops, after a section's key was changed, the new key
  still reaches every reader, including other people and their devices.
  The next upkeep finishes it without changing the key again. Until then,
  **Your devices…** lists the readers still waiting for the key.
- **One refusing section does not hold up the others.** A section whose
  server no longer hosts it, or no longer lets this device read it, is
  reported by name with the server's answer. Other sections' keys are still
  handed on. The refused section stays listed and is tried again later, and
  a refusal never marks a key change finished.

## Install and upgrade

From Settings → Community plugins → Updates. Nothing to migrate.

By hand: put `main.js`, `manifest.json` and `styles.css` from the release
page into `<vault>/.obsidian/plugins/shared-tasks/` and compare them with
these checksums.

## Rolling back to 0.7.2

Install 0.7.2 over 0.7.3 (BRAT: choose version 0.7.2 for
`openlfcp/obsidian`, or put 0.7.2's three files into the plugin folder). The
data format is the same. A key hand-over that 0.7.3 still had to finish is
not shown by 0.7.2. Updating again finishes it.

## Known limits

The limits in [0.7.2](0.7.2.md#known-limits) still apply. In particular,
shared sections on phones remain read-only.

- **An interruption under 0.7.2 is not found automatically.** 0.7.2 (SDK
  0.5.0) could be interrupted after it had adopted a section's new key but
  before handing it on. 0.7.3 cannot see such a key change. The upkeep
  still hands the key to your own devices. Other people's devices keep
  waiting for it until that key change is replayed for the section.
- **A refusal is retried, not abandoned.** A section whose server keeps
  refusing a key, or this device's reads, stays listed and is tried on every
  upkeep. There is no action to give it up.
- The key changes, hand-overs and their recovery were tested with
  simulated devices and against the reference server, but not on a real
  iPhone or iPad with an iCloud-synced vault.
