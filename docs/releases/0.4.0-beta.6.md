Shared Tasks 0.4.0-beta.6: the sixth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.5

**Typing with an input method syncs.** With a Japanese (or another) input
method, deleting text right after a composition could be refused by the
server: the section stayed at "Changes are not safely saved for sync",
and every later edit of that paragraph or task was kept on this device
only. Such an edit now syncs. Nothing is sent while a composition is
open, only the word you commit. A vault left in that state by 0.4.0-beta.5
heals at its next edit of the section: the text the note shows is shared,
and the copy kept on this device is cleared.

**A second section on the same server is shared.** Sharing a section when
another one was already shared on the same server could leave the new
one refused by the server: its invitation did not work and a member's
join was refused. The section is now opened again once the server hosts
it.

**Invitations and joins say what happened.**

- An invitation to a collaboration the server refuses ends with the
  server's code at once, instead of waiting silently for its timeout.
- While an invitation is being created, "Invite collaborator" says so and
  makes no second one.
- An invitation is refused at once while an earlier access change of this
  device still waits for the server (the server would refuse it).
- A join the server refused says so, and that the invitation was not
  used, instead of "Joining needs a connection".

**Refused is not offline.** A section the server refuses shows "Needs your
attention" and says why on its card, never "Offline". When the server
does not host it, Resource status offers "Host on the server now".

**Offline at once.** When the network goes away, the badges say offline at
once instead of after a few minutes, and the sections reconnect at once
when it is back.

**A task cut and pasted one place up or down keeps its move.** Against a
collaborator's move of the same task, both now see one placement
conflict on that task, instead of the other task moving and the
collaborator's move winning silently.

**A removed member's card is consistent.** It counts the refused updates
kept in the note, no longer says access is being checked, and the
member's own row says "refused by the server" or "access removed".

**Diagnostics name shared sections and refusals.** The report names a
shared section's profile and state (it said "(text) · state
unsupported"), and text kept on this device after a refusal, and a
section's save failure, now name the server's code (for example
"rejected 7: INVALID_INTENT 7").

**Requires Obsidian 1.13.4 or later.**

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.6.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.
