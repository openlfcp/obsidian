Shared Tasks 0.4.0-beta.16: the sixteenth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.15

**Typing right after sharing a section never leaves it waiting.** In
0.4.0-beta.15, typing in the first moment after sharing could still,
rarely, leave the section at "needs your attention" with your first edits
unsent. The section now starts from the note exactly as it was shared,
whatever you type meanwhile, and your edits are sent like any others. This
was the known issue of 0.4.0-beta.15.

**Updating or re-enabling Shared Tasks no longer leaves it stuck on
"Loading".** After a BRAT update, or turning the plugin off and on in
Community plugins, the new copy of the plugin could start while the old
one was still closing, find the vault's data in use, and stay that way:
nothing synced and every section showed "Loading shared section" until
Obsidian was restarted. It now waits for the old copy to close. If the
vault really is open in another Obsidian window, a notice says so (see
"If something goes wrong" in the shared sections guide).

**A copy that differs from the shared version says so in one more case.**
When a collaborator's change could not be shown in your note because of
an edit of yours that was never sent, the section said everything was up
to date. It now says "One copy of this section differs from the shared
version", and tries once more.

**Fixes found by testing two vaults editing at once (5,000 runs):**
- Indenting a task with Tab while a collaborator renamed a task under it
  no longer keeps the old title in your note for good.
- Cutting a task together with a subtask you had just indented, and
  pasting it back, keeps the subtask under it. It used to jump to the end
  of the section.
- Pasting several list lines at the start or the end of a task's line puts
  them on lines of their own. The section used to stop syncing, or the
  task's title ran on into the pasted line.
- Pasting a task right after one whose place is in conflict no longer
  stops the section from syncing.
- A task you deleted in an edit the server refused is still deleted on the
  next sync, rather than taken for a damaged link.
- A task you moved and then deleted before it synced is deleted, rather
  than taken for a damaged link.

**The guides are updated for 0.4.0:** sharing a section, its marks and
details, conflicts, offline edits across an access change, and what to do
when something goes wrong.

**Requires Obsidian 1.13.4 or later.**

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta. A
  member on a beta before 0.4.0-beta.14 can keep undoing the others' edits
  while their note is open, and a member on a beta before 0.4.0-beta.4
  keeps seeing "Needs your attention" after someone else chose **Keep it
  deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`. In
   the version field choose **Latest version**: a specific version stays
   installed, and BRAT will not update it.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.16. If it lists an earlier version, see below.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

**Stuck on an older beta?** In BRAT's settings, find `openlfcp/obsidian` in
the beta plugin list. If it shows a version, it is pinned there: edit it and
choose **Latest version** (or remove it and add it again with Latest
version), then run "BRAT: Check for updates to all beta plugins". BRAT's
setting "Select latest plugin version by default" saves choosing.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Rejoining a section you were removed from** isn't supported yet. Your
  local copy stays on your device.
- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- A share hands over the note as it bound it (`SectionCreation` `bound`),
  and the note's next pass first runs a seed-only pass on that text
  (`PassContext.seedOnly`): a section's first base no longer depends on a
  pass running before the user types or composes. A seed-only pass leaves a
  section with a base alone, so it can never take newer edits back.
- A reloaded plugin waits for its previous instance to release the
  vault's writer lock (the stopping kept on the App, which outlives the
  plugin's module); a lock held by another window is reported
  ("lock-held") as before.
- The diverged detector also reports a remote change deferred as
  "local-edit" when nothing will send that edit (not in the pass's batch,
  the coalescer's waiting batch, or held).
- A Task line's indentation is not compared as an edit when rendering a
  remote change; restored nodes pasted with a restored parent keep the
  note's nesting when the model's differs; a paste of list lines is put on
  lines of its own with or without bindings; a placement's predecessor
  must be in the model's list of that parent; a refused pass keeps its
  hints for the next pass (SectionResult.unsent); an insertion hint the
  note no longer binds is dropped.
- The peer-structure property test passes seeds 1 to 5000; the seeds that
  found these fixes run on every test run.
- Unchanged: `@openlfcp/*` 0.2.0-beta.8, spec `mvp-0.2-baseline.12`, the
  reference server at `138030a`, 49 fixtures.
