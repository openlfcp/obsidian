Shared Tasks 0.4.0-beta.13: the thirteenth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.12

This beta fixes ways a shared section stopped syncing, or showed a
collaborator something other than what was shared, when two people
changed its tasks at the same time.

**A task added or pasted right after or under a task a collaborator
deleted no longer blocks sync.** Your note still showed the deleted task,
so a new task typed after it, or a task pasted after or under it, was
placed relative to it. The sync server refused that, and kept refusing
on every try: nothing else you changed in that section was sent, and its
details said the server refused an edit. Now the task is placed after
the nearest task that still exists. One placed under the deleted task
waits until that task is restored (Review conflicts offers it), and
everything else is sent.

**Moving nested tasks keeps their indentation.** When a collaborator
moved a task that had subtasks, a subtask you had indented with Tab
under a task Shared Tasks had written with spaces could end up flush
left, its hidden link line with it. The section then stopped syncing.
Moved tasks now keep their nesting.

**A task moved out of its parent by a collaborator keeps its list
marker.** It could arrive as " [ ] task", no longer a task, and the
section stopped syncing.

**Deleting a task just before closing the note deletes it, rather than
holding the copy.** A task line deleted a moment before its tab was
closed was taken for a damaged link, and the copy stopped syncing until
repaired. It is now deleted, as you meant.

**A cut task pasted under a task you just typed is placed there for
everyone,** even if the task it came from was deleted meanwhile. It used
to stay at its old place for your collaborators, or be hidden from them
entirely, while your note showed it under the new task.

**A collaborator's note is no longer damaged by several changes at once.**
A task moved, another deleted and a third reordered in one update, or a
subtask moved out of its parent while the parent moved too, could leave a
stray "-->" line, a task cut short or missing and a link line twice in
the collaborator's note, and stop that copy from syncing. Changes to a
note are now combined without overlapping.

**Backspace at the start of a task line in Live Preview no longer merges
it into a hidden marker line.**

**A task pasted at the very end of a section no longer breaks it.**
Pasted without its line break at the start of the section's hidden end
line, it joined that line, and the section stopped syncing.

**Two people making the same change at once is no conflict.** Both
completing a task, or both restoring one, used to ask in "Review
conflicts…" which of two identical values to keep. Equal changes now
simply agree.

**A task you add right after another follows it** if a collaborator
moved that task at the same time, as in other collaborative editors.

**Requires Obsidian 1.13.4 or later.**

## Good to know

**Rare: cutting a task while a collaborator nests another task under it
can hide the nested task.** The task is not deleted, but neither note
shows it and nothing is listed to review. A fix is in progress.

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.13.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.2.0-beta.7 (exact versions, from npm
  with provenance, dist-tag `beta`): concurrent equal values of a scalar
  register agree; a connection that closes while the client works is no
  longer an `INTERNAL` error event.
- Spec `mvp-0.2-baseline.12`. Tested against the reference server at
  `138030a` (the baseline.12 pin). The new fixture MS17-empty-adjacent (a
  paragraph marker followed directly by another node marker) passes with
  the parser unchanged: 49 fixtures.
- Placements (moves, restores, creations) follow the nearest sibling the
  model shows under their parent, or one the same batch places; a placement
  under a parent the model does not show waits (§6: INVALID_PREDECESSOR,
  INVALID_PARENT refused the whole batch before).
- The structural writer re-indents a moved subtree by columns (tab stops
  of 4) where its lines mix tabs and spaces, never inserts a moved node
  into its own removed lines, and defers a move whose lines another move
  of the same update takes.
- In Live Preview, a one-character delete never joins a line to a hidden
  binding line (native specs for Live Preview around hidden markers, and
  undo and redo across the plugin's writes).
- A view's move and deletion hints that its pass had not taken yet go to
  the note's next pass when the view closes, the closed note's file route
  included.
- A restored node placed under a parent created in the same batch takes
  the model's place in the projection's base (from the snapshot, hidden
  nodes included), so its placement is sent once the parent is bound.
- Composed changes never overlap where a removal meets an insertion; a
  paste at the start of the section's end line gets its line break.
- A new property test changes the structure in both vaults at once (create,
  delete, cut and paste, Move line, nest), closes and reopens the note, and
  checks after every pass that no note is damaged, nothing is held or lost,
  and both vaults converge. It found eight of the fixes above. The
  interleavings test passed 4999 of 5000 sequences; the one left is the
  follow-the-moved-task behaviour above, now accepted.
