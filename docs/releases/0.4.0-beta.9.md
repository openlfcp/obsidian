Shared Tasks 0.4.0-beta.9: the ninth beta with shared sections.

A pre-release for testers through BRAT: the community directory and
Obsidian's own updates keep offering 0.3.x.

## New since 0.4.0-beta.8

This beta fixes three ways a shared section could lose or garble what you
typed.

**Older text no longer comes back over what you typed.** When you kept
typing while Shared Tasks was saving a change, or started typing with an
input method at that moment, a task you had just edited could get an
older title back a moment later, in every vault and without a warning:
a new task typed, its title deleted, and the old title written back.
What you type now always wins over older text.

**A new task without a title no longer stops syncing.** After Enter on a
task, an empty task line left behind once you clicked elsewhere stopped
every change of that note from being saved for sync. An empty task line
now stays in your note only, until it has a title.

**A blank line before a paragraph stays yours.** Enter at the start of a
paragraph in a shared section split it: the paragraph's text became a new
item, an empty one was left behind, and the other vaults showed an extra
blank line. Now the paragraph keeps its text, and the blank line is
layout in your note only: it is not shared, and nothing is sent.

**Deleting blank lines is safe.** Deleting a blank line in a shared
section could pause it with "One copy of this section has a damaged
boundary or binding line" while the other vaults were fine. Blank lines
can now be deleted freely. A section already paused this way is in order
again by itself.

**Requires Obsidian 1.13.4 or later.**

## Good to know

**When a section is put right, the shared text wins.** If a sync error
left this vault's text different from the shared section, Shared Tasks
shows the shared text again, once you are not typing in it, and says so.
What this vault had and the shared section does not is kept on this
device as a local copy, not sent; the section's card offers to discard
such copies. Merging such text into the shared section is planned for a
later beta.

**An empty paragraph made by 0.4.0-beta.8** (by Enter at the start of a
paragraph) stays in the shared section as an empty line. Delete it in
Source mode, with the line above it, like any other paragraph, if you
do not want it.

## What it is

The features of 0.4.0, described in [0.4.0.md](0.4.0.md): share a whole
section of a note ("Share section…"), with its tasks, paragraphs and lists,
end-to-end encrypted, each section its own collaboration. Shared sections
are on in this beta: there is nothing to turn on.

## Before you install

> **No way back to 0.3.x on this device.** The first start of 0.4 upgrades
> Shared Tasks' sync data on the device and encrypts it at rest. A 0.3.x
> plugin can no longer open it ("Shared Tasks could not start:
> VersionError"); install 0.4.x again and the data is intact. Your notes are
> not affected.

- Try it in a test vault first, or keep a copy of your vault.
- A collaborator still on 0.3.x cannot join a shared section; their shared
  tasks keep working with yours.
- Collaborators on a shared section should all update to this beta: a
  member on a beta before 0.4.0-beta.4 keeps seeing "Needs your attention" after
  someone else chose **Keep it deleted**.

## Install with BRAT

1. Install BRAT from the community plugins.
2. Run "BRAT: Add a beta plugin for testing" with `openlfcp/obsidian`.
3. Enable Shared Tasks. Settings → Community plugins lists it as
   version 0.4.0-beta.9.

If an earlier 0.4.0 beta is installed, BRAT updates it ("BRAT: Check for
updates to all beta plugins"); your identity, collaborations and settings
are kept.

To turn shared sections off, quit Obsidian, add `"sectionsDisabled": true`
to `.obsidian/plugins/shared-tasks/data.json`, and start it again.

## What to report

"Export diagnostics…" prepares a report without note text, names, paths,
keys or links, and shows it to you first. Attach it to an issue at
https://github.com/openlfcp/obsidian/issues with what you did and what you
saw.

## Known limits

The limits of [0.4.0.md](0.4.0.md#limits) apply: about 200 tasks per
section is the qualified size, sections are read-only on mobile, and there
are no headings inside a section.

- **Project server quotas.** The project server (sync.openlfcp.org)
  currently lets one identity host up to 200 collaborations (each shared
  section is one), up to 50 new ones a day from one network, 256 MiB of
  stored data in all and 128 MiB per collaboration. Past a limit, the
  action is refused with "quota exceeded"; nothing already shared is lost.
  These values may change, and the server's operator can set other limits
  for an identity. A server you run yourself sets its own.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.2.0-beta.6, as in 0.4.0-beta.8
  (exact versions, from npm with provenance, dist-tag `beta`).
- Spec `mvp-0.2-baseline.10`. Tested against the reference server at
  `814e913` (the baseline.10 pin).
- A paragraph's marker followed directly by the next one is read as an
  empty paragraph, as it already was before the section's end;
  MARKDOWN-SECTIONS-01 does not cover this case yet, and a fixture for
  it is planned.
- Checked in real Obsidian 1.13.4 and 1.14.4: Enter at the start of a
  paragraph in Live Preview, and the empty line of an empty paragraph
  deleted.
- A randomized test runs typing, deleting, input method commits, Enter,
  the typing timer, interrupted saves, a collaborator's edits and
  reconnecting in random order on two vaults, and checks that no older
  text ever comes back and both vaults agree (500 sequences pass; 382
  failed on 0.4.0-beta.8).
- For what changed in 0.4.0-beta.8 (typing after a section was put
  right), see [0.4.0-beta.8.md](0.4.0-beta.8.md).
