Shared Tasks 0.3.2 (beta): safer with newer collaborations and with a server that lost data.

**Requires Obsidian 1.13.4 or later.** The previous minimum, 1.13.1, was an
Insider-only build; 1.13.4 is the first public 1.13 release. Check Settings →
About before updating.

## Fixes

- **A collaborator's change could be undone right after sharing.** If you
  edited and saved a note within a moment of sharing or inserting tasks in
  it, and a collaborator's change to one of those tasks arrived at the same
  time, the plugin could send the old value back. It now compares your note
  with the shared state as it was when the note was read, and records what
  it wrote at once.
- **Joining a newer kind of collaboration used up the link.** The plugin
  checked the collaboration's kind only after claiming the one-time
  invitation. It now checks first: if the collaboration needs a newer
  version of Shared Tasks (for example the shared sections coming in 0.4),
  you are told to update and join again **with the same link**, which has
  not been used.
- **A newer kind of collaboration was opened as shared tasks.** If one was
  stored on this device (say, after going back from a newer version), 0.3.1
  opened and merged it as shared tasks. 0.3.2 leaves it untouched: "Resource
  status" says it needs a newer version, and every other command says so
  too. Its tasks in your notes are neither sent nor rewritten.

## A server that lost data repairs itself

With the TypeScript SDK 0.1.3 and server 0.3.0 (LFCP ADR 0008):

- If the server lost a collaboration, for example after a restore from a
  backup, Shared Tasks hosts it there again from your device, sends back the
  changes the server no longer has, and shows one short notice ("… was
  hosted again"). Your collaborators' devices do the same.
- While the server catches up, edits wait instead of failing ("Waiting for
  the server to catch up with earlier changes").
- If the server refuses to take the collaboration back, the notice asks you
  to have the owner host it again.
- A collaborator's edit that is waiting for the shared history to settle is
  shown like other edits that cannot be applied yet, after the same delay.

## Under the hood

- The TypeScript SDK is `@openlfcp/*` 0.1.3 (exact versions, from npm with
  provenance). 0.1.2 was published without its code and is deprecated.
- Spec `mvp-0.1-baseline.9`, server 0.3.0.
- A native test harness runs the built plugin in real Obsidian 1.13.4 and
  1.14.4 (`pnpm native`; a manual CI workflow on macOS, Linux and Windows).

## Install and upgrade

From Community plugins (Settings → Community plugins → Updates), with BRAT
(`openlfcp/obsidian`), or by hand: put `main.js`, `manifest.json` and
`styles.css` from the release page into
`<vault>/.obsidian/plugins/shared-tasks/`. Your identity, collaborations and
settings are kept.
